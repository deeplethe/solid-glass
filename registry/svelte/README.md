# Svelte registry

Solid Glass is a React design system, not SolidJS. This additive registry delivers
native Svelte 5 **AskCard and DotLoader** through **shadcn-svelte**, while leaving
every React component, registry name and URL intact. Other components and blocks
are not part of this Svelte release.

## Install

Start with a Tailwind CSS 4 / Svelte 5 project initialized with shadcn-svelte.
After this branch is released to the site:

```sh
npx shadcn-svelte@latest add https://deeplethe.github.io/solid-glass/r/svelte/ask-card.json
npx shadcn-svelte@latest add https://deeplethe.github.io/solid-glass/r/svelte/dot-loader.json
```

Each item installs the shared `src/solid-glass.css` too. Import it **after** the
Tailwind and shadcn-svelte styles in the application's global stylesheet (adjust
the relative path to that file):

```css
@import "tailwindcss";
@import "tw-animate-css";
@import "./solid-glass.css";
```

Keep all imports before ordinary CSS rules. Remove the competing `:root` /
`.dark` color definitions generated by shadcn-svelte, so they do not override
the material. Keep any intentional application overrides after the imports.
Toggle `.dark` on `html` for dark mode. The theme falls back to system fonts if Geist is not installed. Do not
copy the React-only `shadcn/tailwind.css` import from the shared CSS's comment.

```svelte
<script lang="ts">
  import AskCard from "$lib/components/ui/ask-card/ask-card.svelte"
  let chosen = $state<string>()
</script>

<AskCard
  question="Which route?"
  options={["First", "Second"]}
  {chosen}
  onAnswer={chosen === undefined ? (value) => { chosen = value } : undefined}
/>
```

`class` replaces React's `className`. AskCard retains the existing `onAnswer`
callback contract: omit it for an answered card, and pass `chosen` to identify
the answer. The answer buttons remain focusable but inert. DotLoader retains
`dotClassName`; supply an accessible status label in its surrounding context.
`examples/decision.svelte` is a copyable interactive example.

## Architecture and scope

- `src/solid-glass.css` remains the sole material source. The Svelte builder
  embeds it verbatim; no duplicated tokens or versioned npm package is needed.
- `registry/svelte/` owns native `.svelte` source. Never install TSX via the
  Svelte CLI. The `$UTILS$` import marker is intentionally resolved by that CLI
  from the consuming project's configured utils alias; these are registry
  templates, not files to copy directly. Future interactive ports should use Bits UI / shadcn-svelte
  primitives, not a React runtime wrapper.
- `public/r/svelte/` is an additive URL namespace, generated after the existing
  React build (which clears `public/r`). `SOLID_GLASS_ORIGIN` configures dependency
  URLs for a preview server. URLs are not published until the site is released.
- This registry covers **AskCard and DotLoader only**. It does not promise
  parity for stock shadcn-svelte components: shared data-slot names are not
  enough. The current stylesheet also relies on Base UI state attributes,
  DOM structure and Tailwind class names; Bits UI checked/open/active states,
  progress tracks, focus, disabled and portal behavior need dedicated audits.
- No root workspace migration or published npm packages are necessary for a
  source registry. Extract a shared package only when a second consumer needs
  an independently versioned build or runtime API.

## Development

```sh
npm run docs
npm run test:svelte-registry
npm run typecheck
npm run build
```

These commands preserve the React build and test registry generation. The
isolated consumer in `tests/svelte` also installs the built registry through the
real shadcn-svelte CLI, typechecks and builds the installed Svelte source, and
runs browser checks. Its dependencies are separate from the React site.

### Compatibility boundary

AskCard uses native buttons, not Base UI or Bits UI. Its `data-slot="ask-card"`,
`glass-panel`, `glass-chosen`, focus outline, answered/selected classes and DOM
structure match the React component. DotLoader uses the same three spans,
160 ms stagger and canonical reduced-motion rule. Neither port needs framework
state-attribute translation. Keep the controlled `chosen`/`onAnswer` contract:
`chosen` alone highlights a choice; removing `onAnswer` makes the card inert.

Do not treat the shared stylesheet as a supported drop-in theme for arbitrary
shadcn-svelte widgets. Base UI and Bits UI differ in state attributes, portal
markup and track structure. Future checkbox, tabs, menu, dialog and progress
ports must each add a native consumer fixture and state/keyboard/theme tests
before their registry entries are published.

Run the consumer with Node 22 (the CI version) after `npm run docs`:

```sh
cd tests/svelte
npm ci
npm run install:registry
npm run check
npm run build
npx playwright install chromium
npm test
```

The fixture deliberately uses nondefault UI and utils aliases. Browser tests run
against its production build, covering both themes, keyboard choice/focus,
answered-state inertness, reset, small-screen wrapping and reduced motion.

If installed component files are excluded by `.gitignore`, Tailwind 4 will not
scan them automatically. Register their actual directory with `@source` in your
app stylesheet (after the imports), for example:

```css
@source "./lib/components/ui/**/*.svelte";
```

The fixture explicitly registers its gitignored custom UI directory and asserts
rendered padding, rounding, gaps and dot sizes to catch missing utility output.

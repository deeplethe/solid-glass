## Usage

```tsx
import { Composer } from "@/components/ui/composer"
```

```tsx
const [text, setText] = React.useState("")

<Composer
  value={text}
  onValueChange={setText}
  onSubmit={send}
  textareaProps={{ "aria-label": "Message" }}
/>
```

`textareaProps` names and describes the input itself. It accepts `id`, `aria-label`,
`aria-labelledby`, and `aria-describedby`; use its `id` with an external label's
`htmlFor`. Other HTML attributes, including a top-level `id` or `aria-label`,
continue to apply to the outer wrapper.

## While a turn runs

The send mark has no block behind it in any state: its brightness says what it will do. With `running`, it is the quiet square that stops the turn, until something is typed, which is then sent behind it.

The mark is never disabled. With nothing to send and nothing to stop it is dim and does nothing, but it stays where it is, so the keyboard on it is not dropped to the page as the text goes or the turn ends. Sent or stopped from the keyboard, the focus returns to the text; the pointer never takes it away. While the text is being written, the pane's hairline is drawn in the focus line.

## Footer

`ComposerFooter` is the line under the composer, not in it: settings for the message, not part of what is being written. `ComposerPick` is a choice among a few, shown as its current value and held lit while its menu is open.

## API Reference

| Prop | Type | Default |
| --- | --- | --- |
| `value` | `string` | - |
| `onValueChange` | `(value: string) => void` | - |
| `onSubmit` | `(value: string) => void` | - |
| `onStop` | `() => void` | - |
| `textareaProps` | `Pick<ComponentProps<"textarea">, "id" \| "aria-label" \| "aria-labelledby" \| "aria-describedby">` | - |
| `running` | `boolean` | `false` |
| `leading` | `ReactNode` | - |
| `tags` | `ReactNode` | - |
| `above` | `ReactNode` | - |
| `onBackspaceAtStart` | `() => boolean` | - |
